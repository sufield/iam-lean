For `#check String.length`, the expression is even simpler than before because you are not *calling* the function; you are just referencing the function itself.

### 1. The Expression (`Expr`) Tree

Because there are no arguments provided, there are no `Expr.app` nodes. It is a single **`Expr.const`** (constant) node.

```text
Expr.const `String.length [level_params]
```

### 2. Comparison: Applied vs. Unapplied

To understand how Lean builds these trees, look at the difference:

*   **`String.length "Lean 4"`**: This is an **`Expr.app`** node. It combines the function and the argument.
*   **`String.length`**: This is just the **`Expr.const`**. It is the "definition" sitting in Lean's memory, waiting to be used.

### 3. What are `level_params`?

You might see small letters like `u_1` in the Infoview. These are **Universe Levels**. In Lean, everything has a type, and types have types (called Universes). Even a simple constant like `String.length` tracks which "level" of the logical hierarchy it lives in.

### 4. The Command (`Syntax`)

The `#check` command is the outer container in the **Syntax Tree**:

```text
Syntax (node `Lean.Parser.Command.check)
├── Syntax (atom "#check")
└── Syntax (ident `String.length)
```
