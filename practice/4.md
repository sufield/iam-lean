This tree is much simpler because `String.length` is a direct function call rather than a typeclass-based infix operator.

```text
               Expr.app (Application)
              /        \
    Expr.const `String.length      Expr.lit (strVal "Lean 4")
        [level_params]                 (The Argument)
        (The Function)
```

### Why is this tree smaller?

1.  **No Typeclasses:** Unlike `+` (`HAdd`) or `^` (`HPow`), `String.length` is a specific function that only works on strings. It doesn't need to search for a "handler" instance.
2.  **Single Argument:** It only takes one explicit argument, so there is only one `Expr.app` node. 
3.  **No Implicits:** `String.length` doesn't require implicit type arguments (like `Nat` or `String`) because the type is hard-coded into the function definition.

### Internal Logic:

*   **`Expr.const`**: Points to the compiled code for `String.length`.
*   **`Expr.lit`**: Contains the raw string data.
*   **`Expr.app`**: Merges them. When the Lean interpreter sees this specific application, it simply counts the characters in the literal and returns a new `Expr.lit (natVal 6)`.
