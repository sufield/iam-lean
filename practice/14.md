```lean
#guard 1 + 1 == 2
```

This expression combines **Addition** and **Boolean Equality**. In Lean, `==` desugars to the typeclass-based function **`BEq.beq`**.

### 1. The Command (`Syntax`)

`#guard` is a command that evaluates an expression and throws an error if the result is not `true`. It exists in the **Syntax** tree, not the logic **Expr** tree.

### 2. The Expression (`Expr`) Tree

This is a deeply nested tree of **`Expr.app`** nodes because both `+` and `==` are functions that take multiple implicit and explicit arguments.

```text
                    Expr.app (Equality Check)
                   /        \
               Expr.app      [Number 2 Tree]
              /        \
          Expr.app      [Addition (1+1) Tree]
         /        \
     Expr.app      [Instance: BEq Nat] (How to compare Nats)
    /        \
Expr.const    Nat (Type of operands)
`BEq.beq
```

### 3. Deconstructing the "Addition" Branch

The "Addition (1+1) Tree" node above is itself the complex structure we saw earlier:

```text
               Expr.app (1 + 1)
              /        \
          Expr.app      [Number 1 Tree]
         /        \
     Expr.app      [Number 1 Tree]
    /        \
Expr.app      [Instance: HAdd Nat Nat Nat]
  ...          /
Expr.const `HAdd.hAdd
```

### 4. How Lean processes this for your DSL:

When you use `#guard`, Lean performs these steps:

1.  **Parsing:** Creates the **Syntax** tree for the whole line.
2.  **Elaboration:** Fills in all the "hidden" nodes (like the `BEq` and `HAdd` instances) to create the full **Expr** tree.
3.  **Reduction/Eval:** The Kernel (or Interpreter) reduces `1 + 1` to `2`, then reduces `2 == 2` to **`Bool.true`**.
4.  **The Guard:** If the result is `true`, the command succeeds silently. If it were `false`, Lean would stop compilation and show you an error.
