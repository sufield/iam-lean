The output of `#check String → Bool` is **`String → Bool : Type`**.

This represents the **type of all functions** that take a `String` as input and return a `Bool`. In Lean, the function arrow `→` is not just a symbol; it is a fundamental building block of the expression system.

### The Expression (`Expr`) Tree

Internally, Lean represents `A → B` using a node called **`Expr.forallE`** (Forall Expression). Even though we call it an "arrow," Lean sees it as a **Pi Type** (a universal quantifier).

```text
               Expr.forallE
              /     |      \
        "a"        String    Bool
      (Name)      (Domain)  (Codomain)
```

*   **Domain (`String`)**: The type of the input.
*   **Codomain (`Bool`)**: The type of the output.
*   **Binder Name (`"a"`)**: Internally, Lean gives the input a name (usually `a` or `_`), even if you don't use it.

### Why is the result `: Type`?

In Lean’s "Universe" system:

*   `String` is a `Type`.
*   `Bool` is a `Type`.
*   Any function mapping one `Type` to another `Type` is itself a **`Type`**.

1. **`String → Bool`** is a **Type** (specifically, the type of all functions that map strings to booleans).
2. The **Type of that Type** is **`Type`**.

### Why this is a "Core Truth" of Lean:

In Lean, **"Everything has a type."** This leads to a hierarchy:

*   **Value:** `"Hello"` has type `String`.
*   **Function:** `String.length` has type `String → Nat`.
*   **Signature:** `String → Nat` has type **`Type`**.
*   **Universe:** `Type` has type `Type 1` (and so on).

### How this looks in the AST:

When you `#check String → Bool`, Lean looks at the **`Expr.forallE`** (the arrow) and calculates its level:

```text
       Expression: String → Bool
            │
            ▼
      [Internal Expr] ───has type──▶ [Type]
    (Expr.forallE)
```
