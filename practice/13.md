While `#eval` uses the fast compiled code, **`#reduce`** uses the Lean Kernel to expand everything to its most "primitive" form. 

For `#reduce 2 + 2`, the AST represents the **input expression** (the math problem), but the reduction process transforms it into a **canonical form** (the answer).

### 1. The Input AST (`2 + 2`)

This is the "sugar" version. It looks like a complex tree because it includes the typeclass for addition and the `OfNat` wrappers for the numbers.

```text
               Expr.app (Final Application)
              /        \
          Expr.app      [2 (as OfNat tree)]
         /        \
     Expr.app      [2 (as OfNat tree)]
    /        \
Expr.app      [Instance: instHAddNat]
  ...          /
Expr.const `HAdd.hAdd [u]
```

### 2. The Reduced AST (The Result: `4`)

When you use `#reduce`, Lean follows the `Nat.add` definition you just looked at (using `brecOn` or `succ`) and collapses the tree above into the most basic representation of the number 4.

In the Lean Kernel, the number **4** is actually a recursive tree of **Successors**:

```text
       Expr.app (4)
      /        \
  Expr.const    Expr.app (3)
  `Nat.succ    /        \
           Expr.const    Expr.app (2)
           `Nat.succ    /        \
                    Expr.const    Expr.app (1)
                    `Nat.succ    /        \
                             Expr.const    Expr.const `Nat.zero
                             `Nat.succ     (The Base Leaf)
```

| Feature | `#eval` (Compiled) | `#reduce` (Kernel) |
| :--- | :--- | :--- |
| **Philosophy** | "Just give me the answer." | "Show me the logical truth." |
| **Number 4** | Represented as a 64-bit integer. | Represented as `succ(succ(succ(succ(0))))`. |
| **AST Complexity** | Thin/Hidden. | **Transparent/Deep.** Every `succ` is an `Expr.app`. |
