# Tutorial 1: Environment Setup & Kernel Build

**Target Project:** [`sufield/iam-lean`](https://github.com/sufield/iam-lean)  
**Objective:** Set up the Lean 4 nightly toolchain with `elan`, resolve package dependencies with Lake, and build the verification kernel to confirm all mathematical proofs typecheck.

---

## 1. Overview

`iam-lean` is the formal verification kernel for **Stave**, an engine that verifies cloud security boundaries (network paths, IAM trust policies, cross-account access, and CEL predicates). 

Under the Curry-Howard correspondence, a program in Lean 4 corresponds to a mathematical proof:

* A **theorem statement** is a type.
* The **proof body** is a term inhabiting that type.
* **Typechecking is verification.** If `lake build` completes without errors, every security invariant in the repository is mathematically certified.

Because `iam-lean` uses the modern `grind` proof automation tactic and multi-kernel checking features, it requires the **Lean 4 nightly toolchain**.

---

## 2. Prerequisites

You will need a Unix-like environment (Linux, macOS, or Windows via WSL2) with standard utilities:

* `git`
* `curl`
* `make`
* `bubblewrap` (`bwrap`): required by newer Lean tooling for isolated kernel checking.

To install standard build essentials and `bwrap`:

```bash
# Ubuntu / Debian / WSL2
sudo apt update && sudo apt install -y build-essential curl git bubblewrap

# Fedora
sudo dnf install -y gcc make curl git bubblewrap

# Arch Linux
sudo pacman -S --needed base-devel curl git bubblewrap

# macOS (Homebrew)
brew install git make
```

---

## 3. Install `elan` (Lean Version Manager)

Lean projects manage compiler toolchains using `elan` (analogous to `rustup` for Rust or `nvm` for Node.js).

1. Install `elan`:
   ```bash
   curl -sSf https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh -s -- -y
   ```

2. Add `elan` to your active shell session:
   ```bash
   source "$HOME/.elan/env"
   ```

3. Verify the installation:
   ```bash
   elan --version
   ```

---

## 4. Clone `iam-lean` and Configure Nightly

1. Clone the repository and navigate into the project directory:
   ```bash
   git clone https://github.com/sufield/iam-lean.git
   cd iam-lean
   ```

2. Inspect the repository’s pinned toolchain:
   ```bash
   cat lean-toolchain
   ```
   *(This should output `leanprover/lean4:nightly`)*

3. Install and activate the nightly toolchain:
   ```bash
   elan toolchain install leanprover/lean4:nightly
   elan override set leanprover/lean4:nightly
   ```

4. Confirm that the active compiler is pointing to nightly:
   ```bash
   lean --version
   lake --version
   ```

---

## 5. Resolve Dependencies

`iam-lean` manages its dependencies using **Lake** (Lean Make). Resolve dependencies and synchronize the package manifest by running:

```bash
lake update
```

This downloads any pinned proof libraries into `.lake/packages/` and generates/updates `lake-manifest.json`.

---

## 6. Build and Verify the Kernel

Run the primary build command:

```bash
make lean-build
# or directly with Lake:
lake build
```

### What happens during the build:
1. Lake compiles each module in dependency order:
   * `Stave/Basic` (foundational domain types)
   * `Stave/Compose`, `Stave/Network`, `Stave/IAM`, `Stave/CrossAccount`, `Stave/Schema`
   * `Bridge.lean` (contract bridge)
2. Lean's kernel checks every inference step in each proof.
3. If no errors are reported, Lake produces compiled object files in `.lake/build/lib/`.

---

## 7. Verify Proof Completeness (No `sorry`)

In Lean, the `sorry` keyword acts as an axiomatic placeholder for an unfinished proof. To guarantee that no proofs have been stubbed out or left incomplete:

```bash
make lean-verify
```

This target scans all Lean source files in `Stave/` for occurrences of `sorry`. A clean exit indicates that **100% of the theorems are fully machine-checked**.

You can also list all compiled modules verified in the kernel:

```bash
make lean-catalog
```

---

## 8. Setting Up Your Editor (VS Code)

To interactively browse proofs, step through tactic states, and inspect the type theory in real time:

1. Install **Visual Studio Code**.
2. Install the official **Lean 4** extension (`leanprover.lean4`).
3. Open the `iam-lean` root folder in VS Code:
   ```bash
   code .
   ```
4. Open any file (for example, `Stave/Basic/Types.lean` or `Stave/Compose/Monotonicity.lean`).
5. Open the **Lean Infoview** pane (`Ctrl + Shift + Enter` or `Cmd + Shift + Enter`).
6. Place your cursor inside any proof block (`by ...`) to inspect the active proof hypotheses and target goal in real time.
